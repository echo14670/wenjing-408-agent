## 2. 正式 Cache 题工具结果

| 题目 | 关键题意 | 工具核验结果 | 独立重算 |
|---|---|---|---|
| COP005 | 64 KB 直接映射、64 B 块、1 GB 主存 | 行 1024；块号 10 位；偏移 6 位；Tag 14 位 | 一致 |
| COP006 | 32 KB、4 路组相联、64 B 块、32 位地址 | 行 512；组 128；组索引 7；偏移 6；Tag 19 | 一致 |
| COP007 | 命中率 95%，命中 1 周期，主存 100 周期，串行访问 | 6 个时钟周期；serial 模型 | 0.95×1+0.05×101=6 |
| COP020 | 16 KB、2 路组相联、32 B 块；地址序列 | 偏移 5；组索引 8；Tag 19；6 次访问命中 3 次，命中率 50% | 一致 |

工具对“主存容量 1 GB”和“主存地址 32 位”都能推导地址位宽；
“Cache 数据区容量”可直接识别；时间单位支持 `ns` 与“时钟周期”；
地址序列发生组内替换但未给出替换算法时，工具返回 `insufficient`，不会猜测命中结果。

## 4. 模型配置核查

代码实际读取的配置：

| 变量 | 本地验证值 | 是否被代码读取 |
|---|---|---|
| `LLM_API_KEY` | 已配置（不输出、不入库） | 是 |
| `LLM_BASE_URL` | `https://api.deepseek.com` | 是 |
| `LLM_MODEL` | `deepseek-flash` | 是 |
| `LLM_TEMPERATURE` | `0.1` | 是 |
| `LLM_MAX_TOKENS` | `2400` | 是 |
| `LLM_TIMEOUT_SECONDS` | `60` | 是 |
| `LLM_THINKING_MODE` | 旧部署记录存在 | **否** |
| `LLM_REASONING_EFFORT` | 旧部署记录存在 | **否** |
| `LLM_CLEAR_THINKING` | 旧部署记录存在 | **否** |

配置优先级为“进程环境变量 > `backend/.env` > 代码默认值”；
`Settings` 有进程级缓存，修改配置后需重启后端。

三 个 `LLM_THINKING_*` 变量当前没有进入请求参数，不能称为“生效配置”。
本轮已在 `docs/release.md` 中修正，避免运维继续照抄无效项。若后续要启用思考模式，
必须按实际模型供应商实现并通过真实调用验证。
