## 二、实现要点

1. **停止顺序**：`stopChat()` 先读取 `replyDraft` 并写入消息，再清空引用、`abort()`，最后 `persist()`。若先 abort，`finally` 会清空草稿，已生成文字就丢了。
2. **三重写回校验**：每条答疑请求捕获发起时的 `AbortController`、`sequence` 与 `historyId`；分片与最终响应只有三者都匹配才写回，切题、另开会话或重复请求后的迟到数据直接丢弃。
3. **重复请求**：新请求发起前先中止上一条，避免两个流同时写 `replyDraft`。
4. **空占位**：引导模式没有流式分片，停止时仍写一条 `stopped` 占位消息（正文为空），仅用于历史标识；组装 `/api/chat` 时过滤空正文，不送入模型。
5. **历史兼容**：`historyExchange` 消息新增可选 `stopped` 字段，旧备份导入默认 `false`，不影响既有导出/导入。

## 五、已知限制

- **真实模型未复跑**：本机未配置模型 Key，流式停止用本地桩验证。停止逻辑不依赖模型，但真实网络的分片大小与间隔未覆盖，需在候选版用真实模型补一次。
- **不续传同一轮**：停止后继续提问会发起新的 `/api/chat`，服务端不保留被中断的那一轮；已生成文字作为历史消息参与下一轮上下文。
- **占位消息**：仅用于历史展示，正文为空、不进入模型上下文；备份导出中可见 `"stopped": true`。
- **只改前端**：未新增接口字段，`historyId` 仍是浏览器本地会话 ID，跨设备不通用。
- **未覆盖**：浏览器前进/后退导致的卸载中断（当前只 `abort`，不落消息），以及多标签页同时打开同一会话。
